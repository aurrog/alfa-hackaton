# 07. Тестирование

## 1. Стратегия

| Уровень | Что проверяет | Где | Как запустить |
|---|---|---|---|
| Модульные (128) | Домен без БД и сети: машина состояний, скоринговая карта, движок решения (стоп-факторы, ручная проверка, цена, DSCR, контрпредложение, полномочия), калькулятор, подбор продуктов, чек-лист, разбор выписки 1С/CSV, лента, база знаний, реквизиты; отказоустойчивый клиент (повторы, предохранитель); безопасность (Argon2id, JWT); контракт API (OpenAPI, RFC 7807, `X-Request-ID`); LLM-режим и деградация | `backend/tests/unit` | `cd backend && python -m pytest tests/unit` |
| Интеграционные (18) | Настоящая PostgreSQL + API + конвейер + симулятор в процессе: сценарии S1–S5, S7, сбой источника, права доступа, идемпотентность, оптимистическая блокировка, версии политики, проверка файлов, аудит, истечение сроков, дашборд, помощник и заключение | `backend/tests/integration` | `DATABASE_URL_TEST=… python -m pytest tests/integration` |
| Сквозные (8 сценариев) | Публичный API собранного стенда через nginx, реальные задержки симулятора и воркеры | `tests/e2e/run_scenarios.py` | `make e2e` |
| Коллекция Postman | Сценарии S1 и S2 по шагам с проверками | `docs/05-api/postman_collection.json` | `make newman` |
| Интерфейс | Все экраны клиента и банка в Chromium (Playwright): отсутствие ошибок в консоли, вёрстка 1440 px и 390 px | ручной прогон | см. раздел 4 |
| Статические проверки | ruff, TypeScript (`tsc --noEmit`), актуальность сгенерированной документации | CI | `make lint`, `python backend/scripts/gen_docs.py --check` |

CI ([`.github/workflows/ci.yml`](../../.github/workflows/ci.yml)) выполняет всё это на каждый push: линтер и тесты на
PostgreSQL 16, проверку документации, сборку интерфейса, затем собирает стенд `docker compose up -d --build` и
прогоняет сквозные сценарии и коллекцию Postman.

## 2. Результаты последнего прогона

Окружение: Linux x86-64, Python 3.12, PostgreSQL 16, Node.js 22, nginx; стенд запущен теми же процессами, что и в
контейнерах (api ×2 процесса, worker ×2, симулятор, nginx с конфигурацией из `frontend/nginx.conf`), 60 заявок истории.

| Набор | Результат | Время |
|---|---|---|
| Модульные тесты | 128 / 128 ✔ | ≈ 4 с |
| Интеграционные тесты | 18 / 18 ✔ | ≈ 12 с |
| Сквозные сценарии S1–S8 через nginx | 8 / 8 ✔ | ≈ 110 с (из них S6 ≈ 50 с — ждёт окончания сбоя БКИ) |
| Newman: сценарии S1 и S2 | ≈ 40 запросов (с опросом статуса), 29 проверок, 0 ошибок | ≈ 23 с |
| Интерфейс в Chromium: 22 экрана клиента и банка, десктоп и мобильный | 0 ошибок в консоли | — |
| `docker compose config` | конфигурация валидна | — |

Вывод сквозных сценариев:

```

✔ S2  12.0 с  КЗ-2026-000061: бухгалтер → директор → аналитик (выше полномочий) → комитет → 40 млн ₽ / 60 мес. / 18,5% → выдан
✔ S3   7.1 с  КЗ-2026-000062: запрос 3 000 000 ₽ / 12 мес. → 1 500 000 ₽ / 36 мес.: Сумма уменьшена…; Срок увеличен с 12 до 36 мес.

✔ S7   7.0 с  КЗ-2026-000066: свежий ЕГРЮЛ — «ликвидация» → стоп-фактор, автоматический отказ; карточка обновлена
```

Ограничение среды подготовки: в окружении, где готовилось решение, нет доступа к Docker Hub, поэтому сборка образов
выполняется в CI (задание `e2e`); локально проверены все компоненты образов по отдельности — установка Python-зависимостей
из lock-файлов с проверкой хэшей в чистое окружение, чистая сборка интерфейса `npm ci && npm run build`, конфигурация
nginx (`nginx -t`) и `docker compose config`.

## 3. Сквозные сценарии

Пароль всех учёток — `Demo-2026`. Ожидаемые значения рассчитаны для исходного состояния стенда (сценарий S6
зависит от времени: сбой БКИ длится 40 секунд с первого запроса по компании).

### S1. Клиент банка: предодобренный кредит, автоматическое решение, подпись, выдача

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | `anna@kofe.test` открывает главную | Предодобренный лимит до 2 100 000 ₽ с основаниями; лента под общепит в Татарстане |
| 2 | Подбор: «Купить оборудование», 1 500 000 ₽, 24 мес. | Экспресс-кредит — лучший вариант, ставка от 21,5%, платёж ≈ 77 447 ₽ |
| 3 | «Оформить заявку» | Черновик: реквизиты, руководитель, выручка, платежи заполнены, у полей — источник; документы не нужны |
| 4 | Подписать и отправить (согласия + пароль) | Статус «Заявка отправлена»; повторная отправка с тем же ключом не создаёт вторую подпись |
| 5 | Ждать 5–10 с | Проверка данных → Оценка → «Предложение готово»: 1 500 000 ₽, 24 мес., 21,5%, график из 24 платежей |
| 6 | Принять, открыть договор, подписать | «Перечисляем деньги» → «Деньги на счёте»; кредит и график в «Кредитах»; уведомления |

### S2. Роли в компании, ручное рассмотрение, полномочия, кредитный комитет

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | `irina@technostroy.test`: инвестиционный кредит 40 000 000 ₽ на 60 мес., залог — недвижимость 60 млн ₽ | Чек-лист: отчётность, документы по залогу, договор поставки (выписка не нужна — клиент банка) |
| 2 | Загрузить три файла из `test-data/documents` | Пункты чек-листа закрыты |
| 3 | Попытка подписать | 403 — нет права подписи; доступно «Передать на подпись руководителю» |
| 4 | `oleg@technostroy.test` | Уведомление «ждёт вашей подписи»; поручитель (Кузнецов О. В., 70%) подставлен из ЕГРЮЛ |
| 5 | Подписать и отправить | Конвейер → «Рассматривает специалист» |
| 6 | `analyst@bank.test`, досье | Грейд B, рекомендация «Одобрить»; основания: руководитель в анкете не совпадает с ЕГРЮЛ (смена 25 дней назад), сумма выше лимита авто-решения; уровень — кредитный комитет |

### S3. Контрпредложение

`igor@motor.test`: экспресс-кредит 3 000 000 ₽ на 12 мес. → предложение 1 500 000 ₽ на 36 мес. с объяснением:
сумма уменьшена с учётом денежного потока и текущей нагрузки, срок увеличен. Можно принять или отказаться без последствий.

### S4. Отказ с объяснением и персональная лента

`ivan@kozlov-shop.test`: экспресс-кредит 1 000 000 ₽ → автоматический отказ. Причины: просрочка 90+ дней в кредитной
истории, налоговая задолженность. План из 4 шагов, факторы, снизившие оценку, ориентир по повторной заявке. В ленте
появляются материалы «Налоговая задолженность и кредит», «Как восстановить кредитную историю», «Отказ — не приговор»;
лента отличается от ленты `anna@kofe.test`. «Скрыть» убирает карточку, «Полезно» поднимает похожие.

### S5. Счёт в другом банке: запрос выписки и автоматический разбор

`elena@cifra.test`: экспресс-кредит 2 000 000 ₽ на 18 мес., выручка в анкете 2 400 000 ₽ → после отправки «Нужны
уточнения: загрузите выписку». Скачать «Демо-выписку 1С» (или `test-data/statements/kl_to_1c_5406732910.txt`), загрузить
в задачу → выписка разобрана: 12 мес., ≈ 2,5 млн ₽/мес., исключены перевод между своими счетами и поступление кредита →
«Вернуть заявку в работу» → предложение 2 000 000 ₽ под 22%.

### S6. Сбой внешнего источника

`dmitry@logistikpro.test`: кредит на пополнение оборотных средств 6 000 000 ₽ на 18 мес. БКИ отвечает ошибкой 40 секунд →
повторы (видны в журнале вызовов досье) → после исчерпания попыток заявка уходит специалисту с основанием «Источник
БКИ недоступен», а не в отказ. Когда сбой закончился, аналитик нажимает «Перезапросить источники» → сведения получены →
решение аналитика → предложение. Любой сбой включается вручную: `POST :8081/admin/faults`.

### S7. Стоп-фактор по свежему реестру

`pavel@vector.test`: в карточке компания действующая, но свежая выписка ЕГРЮЛ — «в стадии ликвидации» → карточка
обновлена, автоматический отказ `STOP_COMPANY_STATUS`.

### S8. Подключение любой компании

`new@client.test`: некорректный ИНН — понятная ошибка; ИНН с префиксом 99 — «не найдено»; любой корректный ИНН —
карточка из ЕГРЮЛ/ЕГРИП (сгенерированный профиль), подбор, заявка, решение. Чужая заявка — 404, очередь банка — 403.

## 4. Негативные и нефункциональные проверки

| Проверка | Ожидание | Тест |
|---|---|---|
| Без токена / с битым токеном | 401 `unauthorized` / `invalid_token` | unit |
| Чужая компания или заявка | 404 (существование не раскрывается) | integration, e2e S8 |
| Клиент в API банка, аналитик в API клиента, аналитик меняет политику | 403 | integration |
| Подпись без права подписи | 403 `signer_required` | integration, e2e S2 |
| Неверный пароль подписи, нет согласий | 422 `bad_signature_password`, `consents_required` | integration |
| Повтор с тем же `Idempotency-Key` / ключ для другого запроса | ответ из сохранённого, `Idempotent-Replayed: true` / 422 | integration, e2e S1 |
| Решение по устаревшей версии заявки | 409 `stale_version` | integration, e2e S2 |
| Ставка ниже расчётной, решение против рекомендации без обоснования | 422 `rate_below_floor`, `override_comment_required` | integration |
| Возврат в работу с невыполненными задачами | 422 `tasks_open` | integration, e2e S5 |
| Файл с несоответствующей сигнатурой, неизвестный тип, исполняемый файл, путь `../` в имени | 422 / безопасное имя | integration |
| Некорректная выписка | 422 `statement_invalid` с причиной | unit, integration |
| Источник недоступен | ручная проверка, не отказ; повторы и предохранитель | unit, integration, e2e S6 |
| БКИ без согласия | 422 `consent_required` | integration |
| Истечение срока предложения | статус «Срок истёк» | integration |
| Ошибки — RFC 7807 с `request_id` | `application/problem+json` | unit |
| Перебор пароля | 429 после 10 неудач (приложение) и 10 запросов/мин (nginx) | конфигурация |

Ручной прогон интерфейса: Playwright + Chromium, вход под каждой ролью, 22 экрана (главная, подбор, шаги анкеты,
заявка в статусах «предложение», «контрпредложение», «отказ», «выдан»; очередь, досье с вкладками, дашборд, политика,
мониторинг, аудит; мобильная главная 390 px) — ошибок в консоли нет.
