# 08. Демонстрация

## Сценарий показа (10–12 минут)

Подготовка: стенд запущен (`docker compose up -d --build`), открыты две вкладки браузера — для клиента и для банка
(или окно инкогнито, чтобы не выходить из учёток). Пароль всех учёток — `Demo-2026`, вход по клику на странице входа.

| Время | Что показываем | Что говорим |
|---|---|---|
| 0:00 | Страница входа | Две роли — клиент и банк — работают с одной заявкой и одним статусом. Все данные синтетические, внешние системы — симулятор |
| 0:40 | `anna@kofe.test`: главная | Одобренный заранее лимит по оборотам — без документов; сумму можно выбрать ползунком прямо здесь. Ниже — подборка под кофейню в Татарстане, в карточке «почему вы это видите» |
| 1:30 | «Новая заявка»: цель «Купить оборудование», 1,5 млн ₽, 24 мес. | Шаг 1 из 3. Подбор по задаче, а не витрина: продукт выбран автоматически, платёж ещё до заявки, альтернативы рядом |
| 2:30 | «Продолжить» → шаг «Данные» | Было 6 шагов анкеты — стало 3. Всё, что банк знает, свёрнуто в строки-сводки с источником (ЕГРЮЛ, обороты в банке); документы не нужны — чек-лист динамический |
| 3:30 | «Подписать и отправить»: согласия, пароль | Простая электронная подпись: хэш документа, время, IP. Экран «Заявка отправлена», дальше не обновляем страницу |
| 4:00 | Трекер и «Что происходит сейчас» | Пункты проверки получают галочки на глазах: анкета → ЕГРЮЛ, ФНС, БКИ → оценка → решение. Цвет отрезка трекера — чей ход |
| 4:30 | Предложение | 1,5 млн ₽, 24 мес., 21,5%, платёж ≈ 77 447 ₽, переплата, эффективная ставка, график. Принимаем, смотрим договор, подписываем → «Деньги на счёте», кредит в разделе «Кредиты» |
| 5:30 | `igor@motor.test`: 3 млн ₽ на 12 мес. | Контрпредложение вместо отказа: банк объясняет, что изменено и почему (DSCR) |
| 6:15 | `ivan@kozlov-shop.test`: 1 млн ₽ | Отказ, но с причинами простыми словами и планом действий. Главная: лента перестроилась под ситуацию — налоги, кредитная история |
| 7:15 | `analyst@bank.test`: очередь | Очередь с нормативами, грейдами и рекомендациями. Заявки из истории — прошли через настоящий конвейер |
| 7:45 | Досье заявки | Рекомендация движка, расчёт посильной суммы, вклад факторов скоринга, сведения всех источников и журнал вызовов, черновик заключения в один клик |
| 9:00 | Решение сверх полномочий | Кнопка «Одобрить» → отказ по полномочиям → «Вынести на комитет»; решение против рекомендации требует обоснования |
| 9:45 | Сбой источника (S6) | Включаем сбой БКИ — заявка уходит специалисту с пометкой, а не в отказ; перезапрос после восстановления |
| 10:30 | `admin@bank.test`: дашборд, политика, мониторинг | Время до решения, доля автоматических решений, воронка, здоровье источников. Меняем ключевую ставку → новая версия политики, ставки в каталоге изменились сразу |
| 11:30 | Итог | Работающий конвейер, объяснимые решения, документация, тесты и запуск одной командой |

Сбой для показа S6 (если сценарный сбой ЛогистикПро уже прошёл):

```bash
curl -X POST localhost:8081/admin/faults -H 'Content-Type: application/json' \
  -d '{"inn":"*","source":"bki_company","mode":"outage","seconds":60}'
```

Чтобы начать показ с чистого состояния: `docker compose down -v && docker compose up -d --build`.

## Публикация на внешнем сервере

Подойдёт любой бесплатный или учебный VPS с Linux (2 vCPU, 4 ГБ RAM, 10 ГБ диска), например из бесплатного тарифа
облачного провайдера.

1. Установите Docker Engine и плагин Compose (официальный скрипт `get.docker.com` или пакеты дистрибутива).
2. Клонируйте репозиторий и создайте `.env`:

   ```bash
   git clone <адрес репозитория> credit-cabinet && cd credit-cabinet
   cp .env.example .env
   # обязательно:
   sed -i "s/^JWT_SECRET=.*/JWT_SECRET=$(openssl rand -hex 32)/" .env
   sed -i "s/^APP_ENV=.*/APP_ENV=production/" .env
   sed -i "s/^MOCKS_PORT=.*/MOCKS_PORT=127.0.0.1:8081/" .env      # симулятор — только локально
   sed -i "s#^CORS_ORIGINS=.*#CORS_ORIGINS=https://demo.example.ru#" .env
   ```

3. `docker compose up -d --build` — стенд доступен на порту 8080.
4. HTTPS и домен: поставьте перед стендом обратный прокси с автоматическими сертификатами, например Caddy:

   ```
   demo.example.ru {
       reverse_proxy 127.0.0.1:8080
   }
   ```

   и закройте порт 8080 снаружи (`WEB_PORT=127.0.0.1:8080`).
5. Проверка: `curl https://demo.example.ru/api/health/ready`, затем
   `python3 tests/e2e/run_scenarios.py --base https://demo.example.ru --mocks http://127.0.0.1:8081` с сервера.

Если стенд открыт для широкой аудитории, отключите вход в один клик (`DEMO_MODE=false`) и раздайте учётки отдельно —
либо оставьте как есть: все данные синтетические.
